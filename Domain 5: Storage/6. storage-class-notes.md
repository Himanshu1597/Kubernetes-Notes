# StorageClass — Domain 4: Storage

---

## 1. Recap: Provisioning Building Blocks

| Concept | What it does |
|---|---|
| **PersistentVolume (PV)** | The actual piece of storage in the cluster. |
| **PersistentVolumeClaim (PVC)** | A user's request for storage. |
| **StorageClass** | Defines **how** PVs are dynamically provisioned — the plugin, parameters, and policies. |
| **Provisioner** | The driver inside a StorageClass that actually creates the backing storage. |

This note focuses on **StorageClass**. For the static vs dynamic overview, see [pv-provisioning-notes.md](pv-provisioning-notes.md).

---

## 2. What is a StorageClass?

> A **StorageClass** is a Kubernetes object that **specifies the plugin (provisioner) and configuration** that determines how PersistentVolumes are dynamically provisioned.

In plain English: *"When someone asks for storage of this class, use this driver and these settings to create it."*

```
   ┌──────────────────────────────┐
   │       StorageClass            │
   │       (do-block-storage)      │
   │                               │
   │  provisioner: dobs.csi...     │
   │  reclaimPolicy: Delete        │
   │  volumeBindingMode: Immediate │
   └────────────┬─────────────────┘
                │
                ▼   used by
   ┌──────────────────────────────┐
   │            PVC                │
   │  storageClassName: do-block-..│
   └────────────┬─────────────────┘
                │
                ▼   provisions
   ┌──────────────────────────────┐
   │            PV                 │
   │  (created automatically)      │
   └──────────────────────────────┘
```

---

## 3. Why StorageClass — What Challenges Does It Solve?

### Challenge 1: Different Storage Backends Need Different Drivers

A cluster might have AWS EBS, NFS, local disks, or DigitalOcean Volumes all available. Each needs its own logic to create a volume.

**StorageClass solves this** by letting you define one StorageClass per backend, each with its own `provisioner`.

---

### Challenge 2: Developers Should Not Care About the Backend

A developer just wants 10 GB of storage — they should not care if it is EBS or NFS.

**StorageClass solves this** by hiding the backend behind a class name. The developer's PVC only references `storageClassName: <name>`.

---

### Challenge 3: Different Storage Profiles for Different Workloads

You might want **fast** SSDs for databases and **cheap** HDDs for backups. Both can be backed by the same cloud, but with different parameters.

**StorageClass solves this** by letting you create multiple classes — `fast`, `slow`, `archive` — each with different parameters and the same or different provisioners.

---

## 4. The Anatomy of a StorageClass

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: low-latency
  annotations:
    storageclass.kubernetes.io/is-default-class: "true"    # default class marker
provisioner: csi-driver.example-vendor.example              # ① the plugin
parameters:                                                  # ② provisioner-specific settings
  type: ssd
reclaimPolicy: Delete                                        # ③ what happens to PV on PVC delete
volumeBindingMode: WaitForFirstConsumer                      # ④ when to bind/provision
allowVolumeExpansion: true                                   # ⑤ allow PVC resize
```

The **5 important fields**:

| Field | Purpose |
|---|---|
| **`provisioner`** | The plugin/driver that creates volumes (e.g., `kubernetes.io/aws-ebs`, `dobs.csi.digitalocean.com`). The most important field. |
| **`parameters`** | Backend-specific options (e.g., `type: gp3`, `fsType: ext4`). |
| **`reclaimPolicy`** | What happens to the PV when its PVC is deleted — `Delete` (default) or `Retain`. Covered in [reclaim-policy-notes.md](reclaim-policy-notes.md). |
| **`volumeBindingMode`** | `Immediate` (provision now) or `WaitForFirstConsumer` (wait for a Pod). |
| **`allowVolumeExpansion`** | If `true`, PVCs can grow without recreation. |

---

## 5. Important Field — `volumeBindingMode`

> `volumeBindingMode` decides **when** the PV is bound and provisioned.

| Mode | Bind Time | Description |
|---|---|---|
| **Immediate** | At PVC creation | Volume is provisioned and bound the moment the PVC is created. |
| **WaitForFirstConsumer** | At Pod scheduling | Volume binding and provisioning are **delayed** until a Pod that uses the PVC is scheduled. Good for topology-aware storage (the PV is created on the same node as the Pod). |

```
   Immediate:                          WaitForFirstConsumer:
   ┌──────┐  create   ┌────────┐       ┌──────┐  create   ┌────────┐ (Pending)
   │ PVC  │ ───────► │   PV    │       │ PVC  │ ───────► │  ─ ─ ─  │
   └──────┘          └────────┘       └──────┘          └────────┘
                       (auto)                              ▲
                                                            │ Pod scheduled
                                                            │
                                                       ┌────────┐
                                                       │   PV    │ (now created)
                                                       └────────┘
```

> Example: DigitalOcean's `do-block-storage` is **Immediate**. Rancher's `local-path` is **WaitForFirstConsumer**.

---

## 6. Important Field — Default StorageClass

> You can mark a StorageClass as the **default** for the cluster. When a PVC does **not** specify `storageClassName`, Kubernetes uses the default.

Marked using an annotation:

```yaml
metadata:
  name: low-latency
  annotations:
    storageclass.kubernetes.io/is-default-class: "true"
```

`kubectl get storageclass` will show `(default)` next to it:

```
NAME                       PROVISIONER             RECLAIMPOLICY
do-block-storage (default) dobs.csi.digitalocean.com  Delete
do-block-storage-retain    dobs.csi.digitalocean.com  Retain
local-path                 rancher.io/local-path      Delete
```

> If **no** default StorageClass exists and a PVC omits `storageClassName`, the PVC stays **Pending** with the message: *"no persistent volumes available for this claim and no storage class is set."*

> A cluster can have **at most one** default StorageClass — otherwise PVC behaviour is undefined.

---

## 7. Important Field — `provisioner`

The `provisioner` is the plugin name that knows how to talk to the backend. Examples:

| Provisioner | Backend |
|---|---|
| `kubernetes.io/aws-ebs` | AWS Elastic Block Storage |
| `kubernetes.io/gce-pd` | GCP Persistent Disk |
| `dobs.csi.digitalocean.com` | DigitalOcean Block Storage |
| `kubernetes.io/azure-disk` | Azure Disk |
| `rancher.io/local-path` | Local Path Provisioner (Rancher) |
| `kubernetes.io/no-provisioner` | Used for static `local` volumes |
| Any CSI driver name | Generic CSI driver |

> If you do not know the provisioner name, run `kubectl get sc -o yaml` on an existing StorageClass and copy the value.

## 8. Syntax — Quick Reference

### Inspect

```bash
kubectl get storageclass
kubectl get sc                       # short form
kubectl describe sc <name>
kubectl get sc -o yaml               # see all fields
```

### Edit / Patch

```bash
kubectl edit sc <name>
kubectl patch sc <name> -p '{"metadata":{"annotations":{"storageclass.kubernetes.io/is-default-class":"false"}}}'
```

### Generate via Dry-Run

> `kubectl create storageclass` does not exist as an imperative command — you must write the YAML.

### Delete

```bash
kubectl delete sc <name>
```

## 9. Declarative — Full Examples

### Example 1 — Basic StorageClass

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: standard
provisioner: kubernetes.io/aws-ebs
parameters:
  type: gp3
reclaimPolicy: Retain
```

### Example 2 — Default StorageClass

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: low-latency
  annotations:
    storageclass.kubernetes.io/is-default-class: "true"
provisioner: csi-driver.example-vendor.example
allowVolumeExpansion: true
volumeBindingMode: WaitForFirstConsumer
```

### Example 3 — Multiple Tiers for the Same Provisioner

```yaml
# Fast SSD
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: fast
provisioner: kubernetes.io/aws-ebs
parameters:
  type: io2
reclaimPolicy: Delete
---
# Cheap HDD
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: slow
provisioner: kubernetes.io/aws-ebs
parameters:
  type: sc1
reclaimPolicy: Retain
```

### Example 4 — PVC Referencing a StorageClass

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  accessModes: ["ReadWriteOnce"]
  storageClassName: fast            # use the 'fast' StorageClass
  resources:
    requests:
      storage: 50Gi
```

### Example 5 — PVC Using the Default StorageClass

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  accessModes: ["ReadWriteOnce"]
  resources:                         # no storageClassName → default class is used
    requests:
      storage: 10Gi
```

## 10. Demo Walkthrough — Removing the Default Annotation

```bash
# 1. Current state — one default class
kubectl get sc
# do-block-storage (default)   ...
# local-path                   ...

# 2. Remove the default annotation
kubectl patch sc do-block-storage \
  -p '{"metadata":{"annotations":{"storageclass.kubernetes.io/is-default-class":"false"}}}'

# 3. Confirm: no default any more
kubectl get sc
# do-block-storage             ...     (no longer marked default)
# local-path                   ...

# 4. Try creating a PVC without storageClassName
kubectl apply -f pvc-without-class.yaml
kubectl describe pvc <name>
# Events:  no persistent volumes available for this claim and no storage class is set.
```

This is exactly why the default StorageClass matters.

## 11. Exercises to Practice for the CKAD Exam

### Imperative (CLI-based) Exercises

**Exercise 1 — Discover StorageClasses**
1. Run `kubectl get sc`.
2. Identify the default StorageClass.
3. Identify the `VOLUMEBINDINGMODE` of each class (Immediate vs WaitForFirstConsumer).

**Exercise 2 — Inspect a StorageClass**
1. Pick any StorageClass and run `kubectl describe sc <name>`.
2. Identify the `provisioner`, `reclaimPolicy`, and `volumeBindingMode`.

**Exercise 3 — Make a StorageClass the Default**
1. Pick a non-default StorageClass.
2. Use `kubectl patch` to add the `is-default-class: "true"` annotation.
3. Verify with `kubectl get sc`.

**Exercise 4 — Remove the Default Annotation**
1. Find the current default class.
2. Patch it to set the default annotation to `"false"`.
3. Apply a PVC without `storageClassName` and confirm it stays **Pending**.
4. Restore the default annotation.

**Exercise 5 — Delete a StorageClass**
1. Delete a test StorageClass with `kubectl delete sc <name>`.
2. Try to create a PVC referencing it — observe the error.

---

### Declarative (YAML-based) Exercises

**Exercise 6 — Write a Minimal StorageClass**
1. Write a StorageClass manifest named `simple-sc` with:
   - `provisioner: kubernetes.io/no-provisioner`
   - `volumeBindingMode: WaitForFirstConsumer`
2. Apply and verify with `kubectl get sc`.

**Exercise 7 — Default Class via YAML**
1. Write a StorageClass manifest with the default-class annotation set to `"true"`.
2. Apply and verify the `(default)` marker in `kubectl get sc`.

**Exercise 8 — Two Tiers, Same Provisioner**
1. Write **two** StorageClass manifests using the same provisioner but different parameters (e.g., `type: ssd` vs `type: hdd`).
2. Apply both.
3. Create two PVCs, each referencing one of the classes.

**Exercise 9 — `WaitForFirstConsumer` Behaviour**
1. Apply a StorageClass with `volumeBindingMode: WaitForFirstConsumer`.
2. Apply a PVC referencing it — confirm the PVC is `Pending`.
3. Apply a Pod that mounts the PVC — confirm the PVC becomes `Bound`.

**Exercise 10 — Allow Volume Expansion**
1. Write a StorageClass with `allowVolumeExpansion: true`.
2. Apply a PVC with `1Gi`.
3. Edit the PVC's `storage` request to `2Gi` — confirm the PV resizes (some backends may require Pod restart).

## 12. Summary

| Concept | Detail |
|---|---|
| **What it is** | A Kubernetes object that defines how PVs are dynamically provisioned |
| **Most important field** | `provisioner` — the driver that creates real storage |
| **`reclaimPolicy`** | What happens to a PV when its PVC is deleted (`Delete` default, `Retain`) |
| **`volumeBindingMode`** | `Immediate` (provision now) or `WaitForFirstConsumer` (provision when Pod schedules) |
| **Default class** | Marked by annotation `storageclass.kubernetes.io/is-default-class: "true"` |
| **No default + no `storageClassName`** | PVC stays Pending |
| **Multiple default classes** | Not allowed — pick exactly one |
| **API version** | `storage.k8s.io/v1` |
| **No imperative create** | Must write YAML (no `kubectl create sc ...` command) |
| **Inspect** | `kubectl get sc`, `kubectl describe sc <name>` |
| **Related notes** | [pv-provisioning-notes.md](pv-provisioning-notes.md), [reclaim-policy-notes.md](reclaim-policy-notes.md), [access-modes-notes.md](access-modes-notes.md) |
